Deep Research 深度研究

V2 六智能体状态机的完整闭环：规划、检索、分析、写作与对抗审核。

  1. 01
    发起研究POST /research/stream，默认 version=v2，前端用 fetch adapter 读流
  2. 02
    规划ChiefArchitect 输出研究大纲与假设，阶段完成即写检查点
  3. 03
    深度检索DeepScout 最多 3 个章节并发；Bocha 搜索 + 可选 Milvus 本地检索
  4. 04
    分析DataAnalyst 抽取数据点与知识图谱；CodeWizard 执行 Python 生成图表
  5. 05
    撰写LeadWriter 逐章成稿并整合全文
  6. 06
    审核循环CriticMaster 评分；不通过则补充检索或修订（默认最多 1 轮）
  7. 07
    完成research_complete → [DONE]；报告、引用与 UI 状态落 PostgreSQL

知识库 RAG 入库与检索

文档经 DocMind 解析、切片、向量化后进入 Milvus；检索按知识库集合隔离。

  1. 01
    上传POST /knowledge-bases/{id}/documents，后台任务处理
  2. 02
    解析DocMind 每 5 秒轮询，最长等待 300 秒
  3. 03
    切片500 字符 / 50 重叠，优先在中文标点断句
  4. 04
    向量化text-embedding-v4，1024 维，单请求最多 10 条
  5. 05
    入库Milvus 集合 kb_<name>，IVF_FLAT / COSINE / nprobe=10
  6. 06
    检索问题向量 top-k：V2 Scout 10 / 默认 5；Agent 路径不重排
  7. 07
    聊天增强policy_documents + Serper → gte-rerank-v2 → 10 篇 / 12k tokens

资讯与招投标采集

定时任务把外部情报落入业务库；空库时启动即采，避免首屏空白。

  1. 01
    定时触发APScheduler 每日 12:00；空库时 FastAPI 启动即采 20 / 20 条
  2. 02
    行业关键词四套行业档案，关键词与采集配额按行业切换
  3. 03
    拉取Bocha 新闻 + 81API 招投标，按关键词配额切分
  4. 04
    去重新闻按 source_url、招投标按 bid_id 唯一约束
  5. 05
    入库industry_news · bidding_info · news_collection_tasks
  6. 06
    展示/news/list · /news/stats → 资讯页与统计卡片

Chat BI 自然语言数据问答

固定 Schema 的受控 Text2SQL：先生成、再校验、最后执行并可视化。

  1. 01
    提问POST /database/text2sql
  2. 02
    Schema固定三表：industry_stats / company_data / policy_data
  3. 03
    生成 SQLtemperature 0.1；要求 SELECT-only、最多 100 行
  4. 04
    校验关键字黑名单 · 单语句 · 禁止注释与系统表
  5. 05
    执行Text2SQLService 用独立 engine 执行；无 engine 时返回 mock 行
  6. 06
    可视化ChartGenerator 返回 ECharts option JSON 或表格

NOTES / 架构备注

编排真相 LangGraph StateGraph 已编译，但在线研究请求走手写的 _run_simplified（asyncio.Queue）以支持逐事件 SSE；默认审核上限为 1 轮。

未接入 / 遗留 Elasticsearch 仅在 Compose 声明、代码零引用；PolicySearchService、OpenRouter 未进入主链路；RAGFlow 仅服务 /documents 的 list/delete/retrieve 与 /chat/completion/v1。

部署与安全 前后端以宿主机进程运行，Compose 只编排中间件；JWT 未覆盖 5 类路由，CORS 为 *，ServiceConfig 含硬编码回退凭证——生产前需收紧。

运行边界 APScheduler 为进程内单实例，多 uvicorn worker 会重复触发采集；SSE 长连接需要匹配的网关超时与单实例会话策略。

配置缺口 前端行业 ID 为 aviation / finance / healthcare / energy；后端为 smart_transportation / finance / healthcare / energy，aviation 会回退到默认行业配置。
