# 行业信息助手 — 端到端评测方案（航空工业）

> 评测对象：用户提一个航空工业问题 → 系统流式产出带引用的研究报告，即 `POST /research/stream`。
> 结构以已开发的系统为准，题目只取需求文档里的航空工业场景。
> 2026-11-10 做过一次探路运行，第 2 节是实测结果，后面的设计据此调整过。实测发现的缺陷已修复并复测，见第 2 节和第 10 节。

## 1. 被测系统

| 链路 | 入口 | 本方案 |
|---|---|---|
| 深度研究 v2（前端默认）：规划 → 搜索 → 数据分析 → 写作 → 审核 | `/research/stream`，`version=v2` | **主评测对象** |
| 深度研究 v1（ReAct）：计划 → 并行搜索 → 反思 → 报告 | 同上，`version=v1` | 对照组，同一批题 |
| 普通问答 | `/chat/completion` | 二期 |
| Text2SQL、资讯、招投标、股票行情、记忆、附件 | 各自路由 | 不评 |

评测只读对外的 SSE 事件，不 import 内部代码。

### 2.1 探路时的环境

### 2.2 发现并已修复的缺陷

| # | 缺陷 | 链路 | 根因 |

### 2.5 评测设计上的发现

- v2 报告的引用是行内链接 `[来源名](链接)`，v1 是 `##14$$` 形式的编号。两条链路对齐引用要分别处理。
- v2 的最大修订轮数配置为 1，所以审核只会触发一次重写，重写后不再审。
- v2 一题耗时 15–18 分钟，v1 约 3 分钟。
- v2 审核给这几份报告打了 3–4 分（满分 10），指出的问题包括数据自相矛盾、时间线错误。这些是内容质量问题，没有修，正是评测要量化的东西。
- v2 没有接招投标工具。

## 3. 评什么

| # | 维度 | 怎么判 | 方式 |
|---|---|---|---|
| A | 跑通 | 出现结束事件，报告非空，无 `error` | 规则 |
| B | **无证据不成文** | 检索结果为 0 时不产出报告，或明确声明"未检索到资料" | 规则 |
| C | **引用真实** | 引用列表每条都来自检索结果、带正文、是具体页面而不是站点首页；报告里的行内链接都在引用列表里 | 规则 |
| D | 事实忠实 | 报告里的事实断言能被它引用的那条来源正文支撑 | 判官模型 |
| E | 知识库事实准确 | 答案在成飞年报里的题，数字和表述与原文一致 | 规则 + 人工核对标准答案 |
| F | 来源选对 | 知识库题引用了 `local://` 来源 | 规则 |
| G | 要点覆盖 | 预设要点在大纲或报告里出现 | 判官模型 |
| H | 不硬编 | 无答案的题明确说"未公开 / 未找到" | 判官模型 |
| I | 审核生效 | 审核结果被成功解析；判为需修订时修订轮数 > 0 | 规则 |
| K | 搜索模式遵守 | 仅知识库模式下没有任何网络检索事件 | 规则 |
| J | 成本时延 | 总耗时、各智能体耗时、修订轮数 | 规则，只记趋势 |

B、C、I、K 四项是实测后加的，对应第 2 节的缺陷，可用作回归用例。

另看一项**自评可信度**：审核智能体的分数与外部判官的分数是否同向。只出结论，不设门槛。

不评文笔和研判水平，只在周报里放人工抽检意见。

## 4. 题库（航空工业，27 题）

| 层 | 数量 | 说明 | 主要考察 |
|---|---|---|---|
| 行业研究题 | 14 | 需求文档的七个主题各 2 题：集团战略、成飞与沈飞定位、六代机与无人机、舰载机、航发替代、材料供应链、军贸与资本市场 | A C D G |
| 知识库事实题 | 6 | 答案只在 `CF-2025-ANNUAL-SUMMARY.pdf` 里，`search_modes=["local"]` | E F |
| 断供题 | 3 | 只开知识库，问年报里没有的内容，预期检索为 0 | B |
| 无答案题 | 4 | 未公开信息，如某型号未来年产量、未披露合同金额 | H |

断供题和知识库事实题不依赖外部搜索，结果稳定，是门禁的主力。

单题格式：

```json
{
  "id": "cf-sf-posture",
  "query": "成飞与沈飞在十五五期间的战略定位差异是什么？",
  "layer": "research | kb_fact | no_evidence | negative",
  "version": ["v2", "v1"],
  "search_modes": ["web"],
  "expected_aspects": ["成飞定位", "沈飞定位", "对比维度", "不确定性"],
  "expected_answer": null,
  "expected_source": "web | local",
  "sampled_on": "2026-11-10"
}
```

规矩：

1. 知识库事实题的标准答案由人对照年报原文写，并记下页码。
2. 评测用的知识库文档固定，不随业务上传变动。
3. 研究题超过 90 天复核一次要点清单。

原方案里"从种子表反推数值题"取消：三张表是空的，且表结构是通用行业统计，不是航空数据。

## 5. 打分流程

```
发请求 → 原始事件落盘(jsonl) → 取最终报告与引用列表 → 规则项直接判
                                                   → 报告拆成原子断言 → 判官逐条判 → 汇总
```

引用按行内链接对齐：每条断言取它所在句子里的链接，到引用列表里找对应条目的正文。引用没有正文的，该断言直接记"无依据"，不送判官。

断言判四档：支持、部分支持、无依据、矛盾。判官只看来源正文，不许用自身知识。

汇总：

- 支持率 = (支持 + 0.5 × 部分支持) / 全部断言
- 矛盾率 = 矛盾 / 全部断言
- 引用真实率 = 带正文且非首页的引用 / 全部引用
- 要点覆盖率 = 命中要点 / 预设要点

判官上线前校准：人工标 100 条断言，一致率不到 80% 不启用。

## 6. 门槛

| 指标 | 门槛 | 现状（各 1 题） |
|---|---|---|
| 跑通率 | ≥ 95% | 修复后 5 次运行全部跑通 |
| 无证据不成文 | 100% | v2、v1 均过 |
| 引用真实率 | ≥ 95% | v2 仅知识库 100%；v2 联网 100% |
| 审核生效 | 100% | 修复后 2 次均生效 |
| 搜索模式遵守 | 100% | v2 仅知识库过 |
| 矛盾率 | ≤ 2% | 未测，需要判官 |
| 知识库事实准确率 | 100% | 未测，需要标准答案 |

支持率、要点覆盖率、时延：首轮跑 3 次取中位数作基线，之后任一项比基线低 5 个百分点以上判回归。

## 7. 运行节奏

v2 一题 15–18 分钟，30 题全量跑一遍约 8 小时（串行），所以分层更有必要。

| 层 | 时机 | 内容 | 是否阻断 |
|---|---|---|---|
| 冒烟 | 每次提交 | 断供题 1 道，看 A B；约 1 分钟 | 是 |
| 门禁 | 每日 | 知识库事实题、断供题全部 + 2 道研究题；约 2.5 小时 | 是 |
| 全量 | 每周 | 全部题，v2 与 v1 对照 | 否 |

依赖外部搜索的题按最近 3 轮中位数判回归；3 轮内忽过忽不过的题移出门禁，单列观察。并发跑题要控制在博查限流以内，实测 2 条 v2 加 1 条 v1 同时跑没有问题。

### 9.3 判官

位置：`backend/eval/judge.py`。对 `run_eval.py` 落盘的一轮事件流做三项语义判断，不重新发请求。

```bash
.venv/bin/python eval/judge.py eval/traces/<时间戳>
```

```bash
.venv/bin/python eval/judge.py --selftest
```

| 项 | 做法 | 门槛 |
|---|---|---|
| 事实忠实 | 取报告里带引用的句子，和它引用的来源原文一起送判，逐句四档：支持、部分支持、无依据、矛盾 | 矛盾率 ≤ 2% |
| 要点覆盖 | 题目预设的要点，报告是否实质性讨论 | 仅统计 |
| 不硬编 | 无答案的题，三档：拒答、带推演、编造 | 编造 0 |
| 带数字却无引用的句子占比 | 不用判官，直接数 | 仅统计 |

几个设计点：

- 证据只取事件流里该来源的原文片段，判官不许用自身知识。
- 一句话引用几个来源，就把这几个来源的原文合在一起判，只判一次。
- 表格行带上表头送判；参考文献区和"数据来源：…"说明行不算事实句。
- 原文讲的是另一个指标，判无依据而不是矛盾。
- 判官调用失败或没有原文时记为"未判"，不当成通过。

**自检**：16 条构造样例（改数字、改主体、引错来源、表格行、带推演的拒答等），全部符合预期。

**首次运行**（20 份事件流：v2、v1 各 6 道知识库事实题、3 道断供题、1 道联网研究题）：

| | v2 | v1 |
|---|---|---|
| 带引用的句子 | 212 | 155 |
| 完全支持 | 42% | 68% |
| 支持率（部分支持算半） | 68% | 80% |
| 矛盾 | 3 句，1.4% | 1 句，0.6% |
| 带数字却无引用的句子 | 64% | 37% |

- 合计矛盾率 1%，过门槛。不硬编：4 份拒答、2 份带推演、0 份编造。要点覆盖：2 份研究题 4/4。

## 11. 事实性数字逐项验收

两个版本都以发给用户的最终 Markdown 为准。v1 从 `answer` 取正文，v2 从 `research_complete.final_report` 取正文。定稿后按出现位置计数。同一个数在摘要和表格各出现一次，计两次。同一句里的金额、同比和年份分别计数。章节前缀、列表序号、引用编号、链接地址及书目元数据不计。标题中实际断言的年份或金额仍计入分母。

**验收指标 = 有原文支持的事实性数字个数 ÷ 全部事实性数字个数。** 跨报告直接汇总两个计数。零分母显示“不适用”。题目要求数值而报告没有数字时判失败。原有知识库标准答案门槛继续生效。季度题按实际数值出现位置另验报告期和四个季度的原始金额，正确的单位换算及舍入可通过。

| 环节 | 可复核内容 |
|---|---|
| 检索 | 每条网页摘录或知识库切片保留 `source_id`、链接、标题、日期、切片号和原文。同一文档可有多条切片。 |
| 写作 | 章节撰写、整合与修订均可读取真实引文。数字进入定稿前核对主体及指标、数值及方向、单位、适用期间。 |
| 补查 | 先在已检索材料中找可用出处。仍缺证时按原搜索模式补查，再核对。没有依据的数值用缺证标记替换。失去结果的计算或比较分句会被移除，其他已证实的数值继续保留。核对服务失败时该稿不能发布。 |
| 表格 | 带入行、列、表头和单位。同表只有一处原文引用时可共用。混合来源优先按单元格或行匹配。表注只作用于相邻那张表。每个数据仍须在对应原文里成立。文档封面可与本表共同证明报告期，逐字重叠的相邻切片用于恢复原表的行列。合计比较可使用同句明确引用的其他原文作为另一项操作数。 |
| 定位门槛 | `run_eval.py` 从定稿重新枚举数字，按位置核对 `numeric_audit.items` 和原始检索事件。v1 引用匹配到具体切片，v2 由链接和切片标识定位。 |
| 独立语义门槛 | `judge.py` 仅凭定稿、实际引用和检索原文独立给出每个数字的 S、N 或 U。仅 S 计入分子。缺引用、错行列、部分支持、矛盾、调用失败均不能得分。 |

常用命令在 `backend/` 下执行。

```bash
.venv/bin/python eval/run_eval.py --only kb-dividend,kb-quarterly --workers 2
.venv/bin/python eval/judge.py eval/traces/<本轮目录> --numbers-only
.venv/bin/python -m unittest discover -s eval
```

规则回放可离线执行。独立语义复核需要已配置的判官服务。历史事件流仍可做语义复核，缺少新逐项凭据的旧报告会在新的定位门槛下显示缺项。
